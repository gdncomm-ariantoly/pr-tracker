Internal Chrome extension · v0.5.0

PR Tracker

One tab with your open pull requests and the ones waiting on your review, plus every comment from a real person (bots left out) and whether it's been fixed. You get a desktop alert when something changes.

Download pr-tracker-0.5.0.zip 83 KB · Chrome 116+ · github.com (+ optional Jenkins, Claude)

The zip sits next to this page. To share, send the whole folder (this page, screenshot.png and the zip) over Teams or a shared drive.

What it shows

To review

PRs where your review is requested (the toolbar badge counts these), plus open PRs you've already reviewed, so you can see whether your comments were acted on.

Add watched repositories in Settings to also see every open PR in those repos, even when nobody added you as a reviewer. They're labelled Watched repo, sorted after PRs you're on, and can be hidden with one checkbox.

PRs carrying your own comments come first, those with your unfixed comments at the very top, and your comments lead each PR's list.

My PRs

Your open PRs. Each one either says "No human comments" or shows how many comments are fixed and how many aren't.

Each card says who has approved, who asked for changes, and whose review you're still waiting on, people and teams by name.

Each PR shows its latest Jenkins build (passed, failed, running) and links to it, in whichever team folder holds the repo (TRFCEE, SEO, …). Deployment repos (prod-*, nonprod-*) link to their prod or non-prod Jenkins instead; test-automation repos (cucumber-*) show no Jenkins at all.

Both tabs are grouped by service, with PRs that have unfixed comments first, then PRs with other comments, then the rest, newest first; deployment repos come last. PRs with no activity for over a week collapse into a Stale group at the bottom.

Per comment

Author, file and line, the text, a link to it on GitHub, and a status based on what happened next.

ResolvedCode changedFixed (reply) RepliedCommit after No action neededOptional

Install

About three minutes. It isn't on the Chrome Web Store, so you load it as an unpacked extension.

  1. Unzip it into a folder you'll keep

    Chrome loads the extension straight from this folder on every launch, so don't leave it in Downloads. For example:

    ~/chrome-extensions/pr-tracker

  2. Open the extensions page and turn on Developer mode

    Paste this into the address bar (Chrome won't open it from a link). Then turn on the Developer mode switch in the top right.

    chrome://extensions

  3. Click Load unpacked and choose the folder

    Pick the folder that contains manifest.json. A "PR Tracker" card appears.

  4. Pin it to the toolbar

    Click the puzzle-piece icon next to the address bar, then the pin next to PR Tracker. The badge on it shows how many PRs are waiting for your review.

  5. Create a fine-grained token for gdncomm

    Open the link below. It pre-fills the name, Resource owner = gdncomm, and read-only access to Pull requests, Contents and Commit statuses. You still need to pick the repository access yourself:

    • Repository access: All repositories
    • Permissions: Pull requests, Contents and Commit statuses, all Read-only (Metadata: Read-only is added automatically). Commit statuses is what shows the Jenkins build.
    • Expiration: 90 days is pre-filled. Choose anything our org policy allows.

    Create a fine-grained token for gdncomm ↗

    If gdncomm doesn't appear under Resource owner, sign in to the org's SSO on github.com first, then reload the page.

  6. Wait for approval if it says "pending"

    If the org requires approval for fine-grained tokens, the new token shows as pending until a gdncomm admin approves it, and the dashboard stays empty until then. You don't need the "Configure SSO" step used for classic tokens.

  7. Paste it into PR Tracker

    Click the toolbar icon. Settings opens the first time. Paste the token (it starts with github_pat_) and click Save.

Only gdncomm repos appear. A fine-grained token covers a single owner, so PRs in personal or other orgs' repos aren't shown. That's intended.

Your token stays on your computer. It's saved in this Chrome profile's extension storage and sent only to api.github.com. There's no server in between. The extension only reads from GitHub. It never comments, approves or pushes.

Optional extras

Everything above works without these. Each is set up in Settings and stays in this browser.

Jenkins pass/fail

GitHub hides Jenkins builds from fine-grained tokens. Add your Jenkins user ID and API token (Jenkins → your name → Security / Configure → API Token → Add new token) and accept Chrome's prompt for Jenkins access. PR Tracker then reads each PR's last build, read-only.

Claude summaries

Click Summarize with Claude on a PR and Claude judges each comment fixed / not fixed / no action and writes one line on what still blocks it. It's asked only when you click, unless you tick Ask automatically, and answers are reused until the PR changes. Default model Sonnet 5. Two ways to connect, in Settings → Claude:

Claude Code on this Mac — your Claude subscription, no API key. Needs the Claude Code helper (next card). Each summary runs claude -p with no tools, about 15–20 seconds, and counts toward your plan's usage.

Anthropic API key — from console.anthropic.com → API keys (sk-ant-api…), billed per use; set a spend limit.

Either way, comment text, file paths and commit messages go to Anthropic. Check that's allowed for your repos.

Claude Code sessions

Links each PR to the Claude Code sessions on your Mac that reviewed or discussed it, with a copyable claude --resume command, and runs summaries on your subscription. Needs a small local helper and Node.js. From the unzipped folder, run the command shown in Settings:

sh native/install.sh <extension-id> --hook

then Settings → Claude Code sessions → Connect. --hook also marks reviews you post with Claude Code so teammates can see where they came from. --uninstall removes it.

Notifications

Each refresh (every 15 minutes by default, or when you click Refresh) is compared with the previous one. You get a desktop alert for:

  • On your PRs: a new comment, a reviewer replying again in a thread, the PR getting approved or getting changes requested, the Jenkins build failing (and passing again after a failure)
  • On PRs you review: a new review request, one of your comments getting fixed or answered

Every update is also listed in the Updates panel on the right side of PR Tracker, even with desktop alerts off. Clicking an alert or a panel entry opens that comment on GitHub; on hover, ✓ marks an entry read and × deletes it. To check one PR right away, click ↻ on its card instead of refreshing everything. If more than four things change at once, you get one summary instead. You can turn alerts off or change the refresh interval in Settings.

On macOS, allow Chrome to show notifications first: System Settings → Notifications → Google Chrome → Allow notifications. Without this, alerts silently don't appear.

Updating to a new version

Download the new zip and unzip it over the same folder, replacing the old files. Then click the reload arrow on the PR Tracker card at chrome://extensions. Keeping the same folder keeps your token and settings. A new folder counts as a new extension and starts empty.

If something's off

The lists are empty, or "Resource not accessible by personal access token"

Check these in order on your fine-grained tokens:

  • The token isn't still pending org approval.
  • Resource owner is gdncomm, not your personal account.
  • Repository access is All repositories.
  • Pull requests, Contents and Commit statuses are all Read-only.

Fix it on the token page (you don't need a new token), then click Refresh.

"Resource protected by organization SAML enforcement"

You're using a classic token (ghp_…) that isn't authorized for SSO. Either switch to a fine-grained token as described above, or open the classic token → Configure SSO → Authorize for gdncomm.

"GitHub rejected the token (401)"

The token expired or was deleted. Open it on GitHub and click Regenerate token (it keeps the same settings), then paste the new value into Settings.

Chrome warns about developer-mode extensions at startup

This is expected for anything loaded unpacked. Click away or close it. The extension keeps working.

No notifications

Check these three things: the macOS setting above; "Desktop notifications for updates" is ticked in Settings; Chrome is running (checks only happen while it's open).

Also, the first fetch after installing never sends alerts. That's on purpose, so you aren't flooded with everything that already exists.

A comment says "Commit after" but I did fix it

Statuses are a best guess. For the tracker to count it as fixed, resolve the thread on GitHub or reply with something like "Done in abc1234". Replies in Indonesian (sudah, diperbaiki) count too.

A comment counts as unfixed but doesn't need a change

Approvals and clean AI reviews ("No blocking issues", "flagging as solid for a human reviewer") are recognised automatically as No action needed. For anything it misses, click No action needed on the comment. Click Undo to reverse it.

No Jenkins build shows on a PR

Either the PR's latest commit hasn't reported a build to GitHub yet, or GitHub is hiding builds from your token. Make sure the token has Commit statuses: Read-only (edit it, no new token needed) and click Refresh. If builds are still hidden, GitHub doesn't show Jenkins check runs to fine-grained tokens. To see pass/fail, add a Jenkins API token in Settings (the blue banner has a button for it): in Jenkins click your name (top right) → Security or Configure → API Token → Add new token, then paste it with your Jenkins user ID and accept Chrome's prompt for Jenkins access.

"GitHub API error 504" or "Couldn't load … this time"

GitHub took too long. Each list is fetched separately and retried twice, so usually only one list is missing for a moment; the rest still show. Click Refresh to try again.

"Waiting on a team" without the team's name

GitHub hides which team from fine-grained tokens without organization access. Adding Organization permissions → Members: Read-only to the token should reveal it.

A bot account shows up as a person

Some CI accounts are regular user accounts. Add their logins under Extra bot logins in Settings.

PermissionUsed for
storageYour token, settings and the last fetched list
alarmsRefreshing in the background
notificationsDesktop alerts for updates
api.github.comRead-only GraphQL queries that fetch your PRs
*.gdn-app.com (optional)Only once you add a Jenkins API token: lists team folders and reads each PR's last Jenkins build with it
api.anthropic.com (optional)Only once you add an Anthropic API key: asks Claude to judge comments and summarise a PR
nativeMessaging (optional)Only after Connect: talks to the local Claude Code helper, which reads session metadata from ~/.claude/projects and, when you Summarize, runs claude -p with no tools

It can't see your tabs, browsing history, or any other website. It never triggers or changes Jenkins builds, and never comments, approves or pushes on GitHub.
